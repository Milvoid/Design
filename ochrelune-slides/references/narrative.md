# 结构与标题

## 标题即结论

- 每页标题是一句完整的判断，回答“这页想让观众记住什么”。例：“两小时里平均只用约 1 核”，而不是“资源使用情况”。
- 标题 ≤ 20 字，一行放下；必要时用一行说明补充口径（数据来源、样本量）。
- 把全部标题按顺序抄下来，应该能读成一段连贯的摘要。读不通，说明结构有问题，先改提纲再做页面。
- 章节页、封面、结尾页可以用短句或愿景句（“把算力还给科研”），内容页不用诗句和比喻句。

## 常用结构

**项目路演 / 比赛 pitch（8–12 页）**，与 ochrelune-video 的叙事一致：

1. 封面：作品全名、一句话说明、署名、主插画
2. 问题：一个具体例子 + 一个规模数字
3. 问题规模或现状做法的代价
4. 系统是什么：一句话定义 + 系统流程图（输入 → 处理步骤 → 输出 → 人工确认）
5–7. 按流程走一个案例：每页对应流程图里的一到两步，页面角落用同一条流程条标出当前步骤
8. 效果：两三个结果数字，写清测试口径
9. 落地：怎么开始用、需要什么条件、风险怎么控
10. 结尾：愿景句 + 署名

**学术答辩 / 开题（8 分钟约 10–12 页）**：

1. 封面（匿名场合按要求隐去姓名）
2. 研究问题：用一个直观例子讲清问题是什么
3. 为什么重要：现有做法的不足，一两篇关键文献
4. 研究假设或核心思路
5–7. 方法：数据、模型、实验设计，各一页。**方法页要有公式和细节**：模型设定（状态、动作、约束）、关键变量和指标的定义式、估计和检验方法、回归设定里每个系数的含义；每个符号第一次出现时用一句话讲清它是什么。通篇没有公式和方法细节的开题汇报会被认为空洞
8. 预实验或初步结果
9. 进度安排与风险
10. 总结：一句话回答研究问题 + 预期贡献

**课程 Pre（按时长，约 1 分钟 1 页）**：问题 → 背景要点 → 分析（2–4 页）→ 结论 → 讨论问题 → 总结页。

- 案例汇报（课程大纲给了思考题的）：先用两三页讲清案例的业务模式和资金链条，再逐一回答每个思考题，每题给出明确判断。
- 期末小组汇报：按课程大纲对大作业的要求选题和组织；页面上不标“对应第 X 次课”这类来源角标，也不额外加“分析框架”页，课堂所学体现在分析本身里。
- 署名写真名（答辩等要求匿名的场合除外）。
- 两人分讲时，在叙事中间找一个自然的切换点（例如前半场以一个问题交棒，后半场第一页直接回答），讲稿标明前后半场；只有一人讲时也能从头连读。
- 结尾顺序：讨论问题在前，**总结页永远是最后一页**，做法见 [summary-page.md](summary-page.md)。

## 讲稿

- 每页的讲稿写在 `<aside class="notes">`，放映时按 `N` 打开讲者视图或直接看导出的讲稿 PDF。
- 讲稿是口语提纲：这页先说什么、指向哪里、过渡到下一页的一句话。页面上的字是关键词和证据，细节留给讲稿。
- 按 1 分钟约 230 字估算时长（中文口播、脱稿）；超过 250 字每分钟就讲不完。
- 页与页、句与句要有衔接：每页开头一句承接上一页，听众始终知道为什么讲到这里。避免过度凝练、无头无尾的短句，以及没交代清楚就冒出来的说法；术语和机构名第一次出现时讲清它是什么。
- 现场不能看讲稿时，每页先说一句结论，再讲两三个支撑点，便于记忆。

## 数字

- 每个数字都能在原始材料里找到出处，在讲稿里注明。
- 合成或模拟数据在页面上写明“合成”“模拟”；课堂假设推出来的数字标“课堂算例”，和真实披露数据分开。
- 同一个数字在全篇、以及配套的视频和文档里写法一致（千分位、单位、约数）。
