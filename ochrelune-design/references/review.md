# 设计检查与交付

选取任务实际涉及的项目检查。这里不要求每个预览实现全部组件、所有主题或自动化测试。

## 1. 第一眼的层级

- 能否明确指出当前对象、主要内容与主要动作？
- 标题、正文、元信息是否有适度差异，而非全部粗体或全部浅灰？
- 是否通过对齐、间距和表面层次形成秩序？
- 去掉无意义背景效果后，内容是否仍清楚？
- 是否存在过多同等强度主按钮、重复卡片或高饱和装饰？

## 2. 跨页一致性

- 同一保存、取消、导出动作是否使用相同按钮级别？
- 字阶、圆角、输入高度、图标描边与间距是否统一？
- 是否有同义不同值的重复 tokens 或无理由局部覆盖？
- 图表中同一系列是否在不同页面保留身份色？

## 3. 内容、状态与交互

- 使用实际长标题、中文、长文件名、缺失值和异常提示观察布局。
- 检查适用的 hover、focus、pressed、selected、disabled、loading、error、empty。
- 键盘能到达主要操作，焦点可见，不被固定层遮挡。
- 标签、错误说明、图标按钮名称和折叠状态正确。
- 真正可操作的控件确实工作；静态模拟明确反馈，没有假装连接后端。
- 表格排序／图例开关／筛选等操作没有改变未授权的业务语义。

## 4. 可读性与响应式

- 文字与实际表面对比合格，不能只检查色板。
- 必要输入边界、图表线和焦点可辨；轻分隔线没有被误用为唯一操作线索。
- 在一个代表桌面宽度与一个代表窄屏宽度观察；出现问题时再扩展断点检查。
- 整页无意外横向溢出；宽表与代码在自身容器滚动。
- 浏览器字体放大或缩放后，内容和主要操作仍可达。
- 触控不依赖 hover，减少动画设置受到尊重。
- 图表折叠再展开、主题切换或尺寸改变后仍能正确渲染。

## 5. 保真任务的额外检查

- 原文、章节顺序、公式与说明仍一致。
- 表格行列、数值精度、日期区间和缺失值仍一致。
- 图表系列、点值、轴类型、图例与默认范围策略未被篡改。
- 适配函数未修改原始数据对象。
- 原有默认筛选、折叠状态和功能结果未被暗中改变。
- 本地预览不访问业务后端；不可用路由有清楚反馈。

## 6. 有用的行为场景

以下用于自检 Skill 是否引导了正确决策，不要求每次都创建项目：

| 请求 | 预期决策 | 应阻止的偏离 |
|---|---|---|
| 只换肤一份长报表 | 保存原文与全量数据，调视觉 | 只保留近三年曲线、删说明 |
| 新建任务管理界面 | 共用按钮、列表、状态，选择操作模式 | 做成巨型营销落地页 |
| 温和风格设置中心 | 可读字段、错误、焦点和保存反馈 | placeholder 代替标签 |
| 原品牌是蓝色且要求保留 | 保留指定品牌色，借用排版与层次方法 | 强制所有主操作改成陶土 |
| 纯静态聊天预览 | 本地模拟，清楚状态 | 悄悄接入外部模型 API |
| 数据曲线很多 | 稳定映射、线型／标签或合理分面 | 所有线都变浅棕色 |

## 7. 交付用语

交付说明应简短回答：改了什么、保存了什么、在哪看、验证了什么、还存在哪些限制。能附浏览器截图时附一张代表视图；不要把截图当作全部功能验证的证据。

对未测试的主题、打印、浏览器或功能直说未验证，不写“完整支持”。对规范类任务说明哪些是案例验证、哪些是设计建议。不要为了显得完善而新增与请求无关的迁移计划或强制审批。
