# 数据语义与图表设计

用于各类产品中的图表：运营、教育、实验、内容、财务、个人记录等。先按数据关系选择视觉编码，再套用暖纸面、炭黑与陶土的共同风格。不要求固定仪表盘布局、页签数量或绘图库。

## 1. 选择颜色表达的含义

| 数据关系 | 默认做法 | 通用例子 | 避免 |
|---|---|---|---|
| 无序类别 | 类别 ID → 固定类别色，使用 chart-1…6 | 渠道、团队、产品 | 渐变暗示不存在的高低顺序 |
| 有序等级 | 单向明度变化；需要双端强调时可用砖红—米灰—青绿 | 评分档位、年龄区间、实验梯度、20组分组柱图 | 排序后重新分配组色 |
| 连续强度 | 单向顺序色阶，图例说明单位与范围 | 次数、时长、密度 | 任意彩虹或无意义的中心色 |
| 相对基准的偏离 | 发散色阶，基准明确对应中部 | 温差、预算偏差、有符号相关性 | 对称配色却隐瞒中心或不对称范围 |
| 状态 | 固定语义色＋文字／符号 | 达标、失败、未计算 | 把所有低值解释为失败 |

优先通过位置和长度表达精确值，颜色辅助分组、顺序或强调。相同数据关系跨图保持语义；已有地区或品牌约定优先。类别超过色板容量时使用直接标签、线型、选择或分面，不能简单循环六色而声称均可区分。

有序分组的颜色跟随档位，数值正负由柱相对零线的位置和带符号标签表达。若任务重点是正负差异，可改用符号配色并用轴标签标识分组；不要在同一色彩通道混用两套规则。

## 2. 砖红—米灰—青绿

浅色填充锚点：`#a8452f → #ebe9dd → #1f6b62`，对应 `data-low / data-mid / data-high`。保持现有陶土 UI 强调色，数据端点可独立使用青绿。可以反转色带，但图例和同语义图表需同步。

- **有序组双端强调**：按完整组序均匀取色，米灰表示序列中部；偶数组没有单一中心组。它不说明中间组数值为0，也不表示缺失。只需表达越来越强时，选单向色阶更直接。
- **真实中心偏离**：按值映射到色带位置，中心值对应 `t=0.5`。以零为中心且需要对称比较时，范围可取 `[-M,M]`。若使用不对称范围，分别映射中心两侧并标出实际端点；主题换肤保持已有范围策略。
- **顺序强度**：可取米灰→青绿或米灰→砖红，低端仍是有效值。若浅端与底色难辨，使用更深浅端、描边或标签，并检查整体强弱顺序。
- **矩阵**：有符号相关性用明确零点的发散色阶；绝对强度用顺序色阶。缺失用单独的空白／纹理／文字表达，不能画成中点数值。

米灰在暖纸面上较浅。较大柱形或面积可加中性轮廓及标签；细线使用 `data-line-low / data-line-mid / data-line-high`，其中浅色主题的线条中部为较深暖灰 `#82796b`。两套色带共享分组顺序，图例按实际图形展示色样。大量中间组仍可能相近，需要交互或分面，不承诺仅凭颜色逐一辨认。

## 3. 按图形打磨

| 图形 | 呈现建议 | 数据边界 |
|---|---|---|
| 分组柱／条形 | 同级柱宽与间隔一致，组间空隙大于组内；无序渐变不作为装饰 | 新图通常从零基线表达长度；保真换肤不暗改既有轴 |
| 折线 | 清楚的线条、少量必要标记；基准用中性虚线，主要序列适度加强 | 缺失处断开，不因美化插值、平滑或补零 |
| 面积／区间 | 低透明填充＋可辨轮廓；区间带跟随所属系列 | 说明区间含义；堆叠与累计必须符合实际定义 |
| 散点 | 控制点大小、描边与透明度；选中时用轮廓／标签强化 | 大小若编码数值需提供图例；不以抖动暗改观测位置 |
| 热力图 | 明确单位、范围和中心；必要时提供数值读数及行列定位 | 缺失与零分开，不随筛选无提示重定色域 |

网格弱于数据，基准线与普通网格不同；单位、刻度和图例保持可读。图表下方的读数区可为触控、键盘选择提供与 hover 相同的信息。小图减少冗余刻度，不通过过小文字腾空间。窄屏优先调整图例、边距和分面，必要时局部滚动。

## 4. 身份、状态与联动

- **身份**：先从完整语义域建立颜色映射，再筛选和排序。类别 ID 与有序组 ID 保持稳定；同组柱、线和图例使用对应映射。
- **悬停／选中**：保留原色，用轮廓、线宽或标签强化；选择轮廓可用 `data-selection`，不能将选中曲线改成另一类别的颜色。
- **弱化**：降低非重点系列视觉权重但仍可读；不把未选中误画成缺失。区间透明度依实际背景验证，不设置全图统一低透明度。
- **基准／缺失**：分别使用 `data-baseline` 和 `data-missing`。缺失颜色仅是辅助色样，还需文字、纹理或明确空状态；未计算、加载失败、有效零值分别表达。
- **同一设置**：筛选器、标题、图表、指标与对应下载范围保持一致。下钻保留对象和版本；无数据的组合显示原因，不挪用其他设置结果。
- **更新**：保留仍适用的图例选择和缩放；主题／容器变化后更新样式与尺寸。异步切换不让晚到的旧请求覆盖当前对象。

## 5. 可选实现

[chart-colors.mjs](../assets/chart-colors.mjs) 是本包新编写的无依赖颜色工具，仅提供等距锚点间的 sRGB 插值与完整有序域映射，不负责绘图。它不保证感知均匀、相邻色可辨或对比合格。已有库支持合适的色彩空间与色阶时，优先采用项目现有实现。

在支持 ES module 的项目中导入；纯离线页面可按现有打包方式内联或转换，浏览器双击本地 HTML 加载模块的支持需单独验证。

```js
import { orderedColors, sampleRamp } from './assets/chart-colors.mjs';

// root 是图表所在的 .ochrelune-root；主题切换后重新读取并更新图表。
const css = getComputedStyle(root);
const token = name => css.getPropertyValue('--ochrelune-' + name).trim();
const groupIds = allGroupsInSemanticOrder.map(group => group.id);
const fills = orderedColors(groupIds,
  ['data-low', 'data-mid', 'data-high'].map(token));
const lines = orderedColors(groupIds,
  ['data-line-low', 'data-line-mid', 'data-line-high'].map(token));
// 使用完整域的 Map；filteredGroups 排序或缺组不改变颜色。
const barColors = filteredGroups.map(group => fills.get(group.id));
const lineColors = filteredGroups.map(group => lines.get(group.id));
const intensityAt = t => sampleRamp(
  [token('data-mid'), token('data-high')], t);
```

`sampleRamp` 接受两个及以上 `#rrggbb` 锚点和有限数值位置，超出 `[0,1]` 时钳制；调用者负责正确映射数据域，缺失值不传入色阶。`orderedColors` 接受唯一字符串 ID；空域返回空 Map，单组取中点，可按任务改用一个明确类别色。色值使用本包 tokens 的格式，自定义其他 CSS 色彩语法时先转换或使用绘图库的色彩工具。

主题角色的跨库映射示意：

| Token／角色 | Plotly 示例字段 | 其他绘图库的对应职责 |
|---|---|---|
| surface、text-secondary、font-sans | paper_bgcolor、plot_bgcolor、font | 画布、刻度／图例文字、字体 |
| grid、zero-line | xaxis/yaxis.gridcolor、zerolinecolor | 网格、零线 |
| 类别／分组映射 | trace.line.color、marker.color | 系列线条、柱／点填充 |
| data-baseline、data-selection | 单独基准 trace、选中轮廓配置 | 基准、选择状态 |

按库支持的更新方式注入这些字段，保留原数据、formatter、轴类型和范围；不要对所有 trace 类型套同一对象。导出图像显式设置背景并检查文字、色样与透明填充。无需引入特定库、后端或在线字体。

## 6. 验证范围

按本次实际图形检查：分组过滤后的颜色、浅色填充和细线、负值和有效零值、缺失、单组、密集图例、选择与导出。数据量适用时观察2组和20组等不同密度，不要求小任务制造所有场景。深色 tokens 是独立起点，须在实际背景上复验；静态色板或插值测试不能代替视觉及交互检查。
