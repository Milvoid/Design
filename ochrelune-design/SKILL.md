# Ochrelune Design · 温和编辑感

将暖纸面、清楚的排版层级、小面积陶土强调和统一控件用于真实任务。以 Duply 的审美分析、ndroussi 的组件参考及 Impeccable 的打磨方法为来源，经裁剪统一；不冒充 Claude 官方设计系统。不依赖这些仓库或专有字体即可使用。

## 先确定任务边界

从用户请求和当前项目识别以下内容，能推断时直接推进，不要求填写问卷：

- **任务类型**：新建界面、现有界面换肤、组件统一或设计评审。
- **页面用途**：操作工具、阅读内容、品牌展示，或明确分区的混合页面。
- **保留项**：文案、数据、信息顺序、路由、业务行为、已有品牌要求。
- **环境**：已有框架、样式系统、组件库、真实数据或静态样例、支持的设备。

“只改样式”“保持内容”意味着保留文案、公式、数据、精度、顺序及功能语义。不能借设计优化改写内容、缩短数据区间、重算指标或隐藏重要信息。用户授权信息架构重做时再调整结构。

## 核心规则

1. 暖白底、炭黑主文字、暖灰次级表面；陶土色用于少量链接、选择和反馈。绿色只在领域语义需要时出现，不作为默认主题。
2. 层级来自字体、对齐、间距和有限表面色阶。默认不加玻璃、发光、悬浮卡片阵列、装饰性渐变或入场动画。
3. 工具控件使用无衬线字体；衬线用于阅读型页面标题或少数编辑式段落。表格使用等宽数字，代码才需要等宽字体。
4. 同一功能跨页使用相同组件与状态；主操作通常为炭黑实底。圆角与密度统一，避免所有元素胶囊化。
5. “克制”不能降低可读性和可操作性。重要文字、输入边界、焦点、错误和图表系列必须可辨识。
6. 适配现有技术栈，不因本 Skill 引入框架、后端、远程字体、分析脚本或外部服务。静态预览只使用本地资源或明确的模拟数据。
7. 图表颜色与 UI 强调色分开管理；保持系列身份与数据语义，颜色不足以区分时用线型、标记、标签补充。

## 实施流程

1. 阅读项目约定，观察代表页面及共享组件。保留可用结构，明确一次要解决的视觉问题。
2. 选择阅读、操作或展示模式；确定一套字阶、密度、内容宽度和强调色职责。
3. 将 [assets/tokens.css](assets/tokens.css) 映射到现有语义变量；它是可调起点，不是要求覆盖全部项目。需要基础控件时参考 [assets/primitives.css](assets/primitives.css)，挂在 `.ochrelune-root` 内，避免全局侵入。
4. 先完成一个代表性页面或组件，再复用到授权范围。补齐适用的 hover、focus、active、selected、disabled、loading、error、empty 状态。
5. 用真实长标题、表格、说明和错误状态检查桌面与窄屏；保真任务额外比较原文及数据。修复已观察到的问题，不为小任务扩大成全站审计。
6. 交付预览或文件链接，简述视觉变化、验证内容和未完成范围。不要宣称只凭静态截图已完成无障碍或完整功能认证。
