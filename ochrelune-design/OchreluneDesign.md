# Ochrelune Design：温和编辑感界面设计规范

名称：Ochrelune Design，取赭色（ochre）与月亮（lune）的组合意象，呼应陶土与暖白。

版本：1.0 · 2026-09-28  
适用对象：Web 应用、工具、工作台、阅读页面、研究报告、知识库、设置与管理界面。  
定位：受 Claude / Anthropic 视觉语言启发的独立、跨项目设计规范，采用暖白、炭黑、陶土色和编辑式排版。不是官方品牌规范，也不要求复制其标志、字体或产品文案。

## 1. 设计理念：内容稳定，界面安静，操作明确

这套风格的价值在于长期使用时的信息秩序：用户能快速辨认当前对象、阅读内容、比较数据并完成操作。暖色纸面建立柔和基调，炭黑承担清晰的信息骨架，陶土色用于少量有意义的强调。界面有层次，但不依赖持续吸引视线的材质特效。

“现代日式的高级感”在这里用作审美描述：自然、温和、克制、留白和精确。它不是对 Claude 品牌历史的事实判断，也不意味着要添加日式图案、纸纹、禅意插画或装饰符号。

### 1.1 稳定的设计原则

| 原则 | 实施方式 | 要避免的问题 |
|---|---|---|
| 内容优先 | 先建立阅读顺序、标题和主要操作，再决定容器 | 为配合模板删减内容或虚构指标 |
| 温和且清晰 | 暖中性色，足够的文字对比，少量实色锚点 | 全部文字浅灰、重要按钮无辨识度 |
| 结构提供层次 | 字阶、对齐、间距、表面深浅和细分隔线 | 每段内容套浮动卡片，层层套框 |
| 组件可预测 | 同义动作保持相同按钮级别与状态 | 每页设计一套新控件 |
| 保持信息密度 | 密集区域紧凑，主要分组之间留白 | 大标题和空白挤占工作空间 |
| 装饰有理由 | 图片承载内容；动效说明状态 | 氛围光斑、玻璃、粒子和无意义计数动画 |
| 可复用而可调整 | 语义变量和页面模式控制变化 | 用同一布局套所有产品 |

### 1.2 如何避免“过于 flat”

单纯移除阴影和色彩容易得到没有层级的页面。应保留三种差异：前景文字的强弱、相邻表面的明度差、相关与不相关内容之间的间距差。必要时，主按钮或当前对象提供一个明确的视觉锚点。

常用组合：纸面背景＋浅暖灰侧栏＋清楚的标题＋轻分隔线＋炭黑主操作。图表可以有独立边界；连续文章段落通常不需要卡片。下拉菜单和模态框具有真实覆盖关系，可以使用轻阴影。页面主体不需要通过 hover 上浮来证明可交互。

## 2. 来源分工与统一裁剪

这套规范采用“Duply 审美骨架＋ndroussi 应用组件参考＋Impeccable 一致性与打磨流程”的组合，具体出处见 [来源说明](references/provenance.md)。三者提供参考，不同时充当互相竞争的规则。

| 来源 | 吸收内容 | 本规范的裁剪 |
|---|---|---|
| Duply-AI 对 Anthropic 的社区分析 | 暖纸面、墨色、陶土强调、编辑式排版、温和表面层次 | 营销页的大字号、宽间距、方形大按钮不直接用于工具页 |
| ndroussi 的社区设计文档 | 按钮、表单、侧栏、聊天、弹窗、状态和主题的覆盖范围 | 不移植 Claude 身份文案、默认 blur、彩色粗侧边条或每卡片 hover 阴影 |
| Impeccable | Operate / Read 模式区分、统一状态、quieter 思路和最终打磨 | 具体品牌表达服从当前任务；不强制引擎、hooks、扩展或命令链，不照搬与本方向冲突的细则 |
| 已完成的静态预览 | 标题与正文分工、细边框控件、暖灰公式块、低噪声图表 | 案例的小字号、特定结构及色值不自动成为所有产品的硬性要求 |

规范强度：**必须**用于内容保真、语义正确、可用性和当前用户约束；**默认**用于本风格的主要选择；**建议**为可按内容调整的起点。具体数值除已标明标准者外，均为本规范推荐值，不声称来自官方采样。

## 3. 页面模式与任务范围

### 3.1 按使用任务选模式

| 模式 | 常见对象 | 排版和密度 | 视觉重点 |
|---|---|---|---|
| Operate 操作 | 管理台、搜索、表单、任务列表、分析工作台 | 无衬线为主，固定 rem 字阶，标准或紧凑密度 | 控件一致、选中状态、错误恢复、扫描效率 |
| Read 阅读 | 文档、文章、报告说明、知识库 | 更舒展正文，可用衬线标题，限制行长 | 章节关系、长文阅读、图文与引用 |
| Present 展示 | 产品介绍、作品、发布说明首页 | 更大标题与段间距，可加强品牌表达 | 明确主题与少量高质量视觉内容 |
| Mixed 混合 | 带图表的报告、文档加设置、聊天加工具 | 分区使用上述模式，保留共同变量 | 避免同一页面上每个区域都有不同风格 |

不按行业强制模式。金融报告也有阅读区，内容平台也有密集管理后台；以该区域的任务判断。

### 3.2 新建、换肤与重构

- **新建**：允许根据需求设计信息架构与组件，模拟内容需明确标识。
- **保真换肤**：保留原文、信息顺序、数值、公式、数据范围、业务行为和路由语义，只调整呈现。
- **组件统一**：把重复实现收敛为共享组件，不暗中改变交互结果。
- **信息架构重构**：仅在授权范围内调整分组、导航或内容表达，交付时说明变化。

换肤时，改字号、间距、网格列数与颜色通常属于呈现；把原先直接可见的说明折叠起来、删列、改变默认筛选和截取数据区间会改变信息可达性，需要单独判断授权。

## 4. 色彩系统

### 4.1 三层变量

使用“基础色 → 语义角色 → 组件引用”的层次。基础色描述色值；语义变量描述用途；组件仅消费用途。不要在多个按钮、图表和侧栏里各写一套接近的 hex。

| 语义变量 | 浅色默认值 | 用途 |
|---|---|---|
| `--ochrelune-canvas` | `#faf9f5` | 整体暖纸面 |
| `--ochrelune-surface` | `#fcfbf8` | 内容容器、输入与浮层底色 |
| `--ochrelune-surface-subtle` | `#f5f3ed` | 次级区、选项组、辅助区域 |
| `--ochrelune-surface-muted` | `#f0eee6` | 侧栏、代码块、表头 |
| `--ochrelune-surface-strong` | `#e8e6dc` | hover、较强的中性分组 |
| `--ochrelune-text` | `#2b2925` | 标题、主要内容 |
| `--ochrelune-text-secondary` | `#58534a` | 次级正文、辅助控件 |
| `--ochrelune-text-muted` | `#6b655b` | 元信息；仍应可读 |
| `--ochrelune-border` | `#e3dfd5` | 内容分隔线，不承担唯一控件边界 |
| `--ochrelune-control-border` | `#8b8377` | 需要通过边界识别的输入框等 |
| `--ochrelune-accent` | `#9f5038` | 正文链接、焦点与少量强调 |
| `--ochrelune-accent-soft` | `#f2e2d9` | 选择背景、温和强调区 |
| `--ochrelune-action` | `#2b2925` | 主操作实底 |
| `--ochrelune-on-action` | `#faf9f5` | 主操作文字 |

配套 tokens 文件是精确实现来源；表格用于理解角色。不要为了使所有边框“轻到看不见”而统一使用 `--ochrelune-border`。装饰性分隔线与必须辨识的输入边界需要不同强度。

### 4.2 陶土色的职责

品牌参考中的 `#d97757` 可用于装饰性小面积强调或经过验证的大图形，但不直接作为所有小字号文字的前景。正文链接默认使用更深的 `#9f5038`。主操作默认炭黑；选中、焦点和链接可以用陶土色，这样页面不会被橙色按钮填满。

强调色占比以少量为原则，不强制一个百分比。检查视线是否被无关区域反复拉走，比计算色块面积更有用。

### 4.3 状态色和业务色

| 状态 | 建议前景 / 浅背景 | 表达方式 |
|---|---|---|
| Success | `#42644e` / `#eaf0e9` | 对勾或文字，如“已保存” |
| Warning | `#815b26` / `#f5eddf` | 明确说明影响与下一步 |
| Danger | `#a13e32` / `#f8e9e5` | 错误说明、必要的危险操作 |
| Info | `#496879` / `#eaf0f3` | 说明性信息，避免装成警告 |

绿色可用于成功或领域语义；它不作为页面默认品牌色。金融涨跌色遵循产品既有地区约定，不把陶土色自动解释为下跌，也不把绿色自动解释为盈利。所有重要状态同时提供文字或符号。

### 4.4 避免混淆

选择状态、错误状态和业务数值是不同信息，不能共用“橙色就是强调”含糊处理。选中行可使用浅陶土背景和明确的选择标记；错误字段使用错误文案和危险色；数据系列使用独立调色板。

## 5. 字体与排版

### 5.1 字体职责

- **Sans 无衬线**：导航、按钮、标签、表单、表格、工具界面的正文与标题。
- **Serif 衬线**：阅读或展示页面的主标题，少量较长阅读内容；不铺满控件。
- **Mono 等宽**：代码、原始表达式、标识符、需要对齐的机器输出。普通数字优先使用无衬线加 `tabular-nums`。

默认使用系统字体，包内不携带专有字体。可在许可和性能允许时自托管合适的开源字体；不要把 Anthropic Serif、Styrene 等名字写进 CSS 就宣称复刻完成。实际部署要检查 fallback 和中英文混排。

推荐基础栈：

```css
--ochrelune-font-sans: -apple-system, BlinkMacSystemFont, "Segoe UI", "PingFang SC", "Microsoft YaHei", sans-serif;
--ochrelune-font-serif: Georgia, "Songti SC", "STSong", serif;
--ochrelune-font-mono: "SFMono-Regular", Consolas, "Liberation Mono", monospace;
```

### 5.2 推荐字阶

以浏览器默认 16px 根字号举例，实际使用 rem；不固定或降低根字号。

| 角色 | 操作界面 | 阅读界面 | 字重 / 行高 |
|---|---|---|---|
| 页面标题 | 28–32px | 36–44px，窄屏 28–32px | 400 衬线或 600 sans / 1.25–1.4 |
| 章节标题 | 18–22px | 22–28px | 500–600 / 1.4 |
| 组标题 | 15–16px | 17–18px | 600 / 1.5 |
| 正文 | 14–16px | 16–18px | 400 / 1.6–1.8 |
| 控件 | 14–16px | 14–16px | 400–500 / 1.4–1.5 |
| 元信息 | 12–13px | 13–14px | 400 / 1.5 |
| 表格数据 | 12–14px | 依数据密度 | 400 / 1.5 |

案例中存在 11–13px 的密集报告文字，那是案例配置，不应成为通用产品正文默认值。不要通过缩小文字解决空间不足。

### 5.3 行长、字距与对齐

英文长文起点约 65–75ch；中文以约 30–40 个汉字一行的阅读区起步，再按设备和内容调整。`ch` 是西文字形度量，不等同于汉字数。混排长文通常限制在约 42–48rem。

正文使用自然字距。英文大标题可微调负字距；中文标题默认不压字。避免给中文加英文大写标签式的夸张 letter-spacing。标题上方留白一般大于它与所属正文之间的间距。

段落左对齐；不为了形式对称而把说明、长表单或数据解释居中。数值右对齐，名称左对齐，单位和小数位遵循业务约定。不要为了排版擅自四舍五入既有结果。

## 6. 布局、间距与信息密度

### 6.1 间距标尺

使用 4px 基础步长，常用 `4 / 8 / 12 / 16 / 20 / 24 / 32 / 48 / 64`。例外可以存在，但应来自真实组件尺寸，不以零散魔法数字积累。

- 图标与文字：6–8px。
- 标签与字段：6–8px。
- 相关字段或工具：12–16px。
- 独立组件：20–24px。
- 主要分区：32–48px。
- 展示页面章节：48–80px，按内容选择。

连续相关内容应靠近；留白表达分组。不要给所有层级都设置相同 24px gap。

### 6.2 内容宽度

| 页面 | 推荐起点 | 说明 |
|---|---|---|
| 阅读 / 文档 | 42–48rem | 图表可局部扩宽 |
| 设置表单 | 36–44rem | 避免字段横跨整屏 |
| 一般应用 | 72–80rem 或随工作区扩展 | 由侧栏与内容共同约束 |
| 数据分析 | 76–90rem 或流式 | 表格保留局部横向滚动 |
| 窄屏 | 左右 16–20px | 操作区可换行或折叠次级入口 |

宽度是起点。工作台可利用大屏，不强制所有应用变成居中文章。Grid 子项设置 `min-width: 0`，弹性布局中的长文本也要允许缩小，避免内容把整页撑宽。

### 6.3 密度选项

只在任务需要时提供紧凑与标准密度。优先改变行高和 padding，保持字体可读与命中区域足够。紧凑表格可减少行距；触控入口不能一起缩成难点中的小按钮。

### 6.4 页面骨架

- **工具页**：轻量顶栏／侧栏 → 页面标题与主要操作 → 筛选与工具栏 → 数据或任务主体 → 分页／辅助说明。
- **阅读页**：标题与必要元信息 → 摘要或开篇 → 连贯章节 → 图表与注释 → 引用或相关操作。
- **详情页**：对象标题 → 状态与关键属性 → 内容／历史／设置分区 → 适当的次级操作。

这些是新建时的参考结构。保真换肤不因模板不同而移动现有内容。

## 7. 表面、形状与深度

### 7.1 层次模型

1. 页面纸面作为稳定底色。
2. 侧栏、表头、辅助区使用浅暖灰。
3. 独立内容模块通过间距、细边界或稍亮底色区分。
4. 覆盖式菜单和对话框使用不透明表面，可配轻阴影。

普通内容容器默认无阴影。只需一种分组手段时，不同时叠加强色底、粗边框和阴影。细线用于结构，不给每个段落画框。阴影表达覆盖关系，不表达“高级”。

### 7.2 圆角与形状

控件默认 6px；内容容器 8px；对话框可 12px。紧凑报告可采用 4–6px。圆形留给头像、圆形图标按钮等真正圆形对象；胶囊适合少量标签和分段选择，不用于全部按钮与卡片。

默认禁用装饰性背景模糊、发光描边、渐变文字、噪点纹理和鼠标跟随光效。地图、画布等真实内容需要网格时可以用网格，普通工作台不铺装饰网格。

## 8. 组件规范

### 8.1 按钮与链接

| 级别 | 外观 | 用途 |
|---|---|---|
| Primary | 炭黑底、暖白字 | 当前区域最重要的提交／创建／保存 |
| Secondary | 透明或纸面底、中性边界 | 次要动作、切换与导出 |
| Ghost | 无常驻边框，hover 有中性底 | 工具栏中的低权重动作 |
| Danger | 明确危险色与文字 | 删除等具有破坏性的动作 |
| Inline link | 深陶土字与下划线 | 正文中的导航或引用 |

同一区域避免多个同等强度主按钮。使用动词与对象作为标签，图标不能代替必要文案。导航使用链接，操作使用按钮；不要用 div 模拟按钮。图标按钮提供可访问名称和足够的点击区。

按钮高度标准约 40px，触控常用 44px 或更大；紧凑桌面控件可约 32px，仍需检查目标间距。加载时保留宽度，避免标签变化使布局跳动；不能重复提交的操作正确禁用或去重。

### 8.2 输入框、选择与表单

标签始终可见，placeholder 用作示例而非唯一标签。输入底色比页面略亮，边界足以辨认，focus 为明确的陶土描边；不使用发光光圈替代清晰边界。

同类字段统一高度、圆角与内边距。长文本使用 textarea；数值、单位、范围与格式说明相邻放置。错误位于字段附近，说明原因和修复方法，使用 `aria-describedby` 和 `aria-invalid` 等语义。

选择器优先沿用项目已有可靠实现。复选框用于多选或确认，单选框用于互斥选择，开关用于即时生效的布尔设置。需要统一提交的表单要说明保存行为，避免用户误以为开关已自动保存。

### 8.3 Tabs、分段选择与筛选

页面章节切换适合下划线 Tabs；少量互斥展示方式适合浅灰轨道内的分段选择。当前项通过字重、下划线或底色明确标识，不仅改变很轻的颜色。

筛选区组织输入、已选条件、清除与结果数量。筛选条件是业务内容，保真换肤时不能改变默认值。筛选导致零结果时提供“清除筛选”等有用恢复入口。键盘操作遵循组件语义，不把任意按钮群都标成 tabs。

### 8.4 导航与侧栏

侧栏使用中性浅表面和稳定宽度，当前页有明确标记；避免每项配彩色图标块。路径信息使用面包屑；工具切换与对象内 Tab 的职责分开。折叠后的图标导航要有可读名称。

固定导航只在长列表或持续操作中有实际价值时采用，不能遮盖焦点、锚点标题或移动端大部分空间。移动端抽屉关闭后将焦点返回触发按钮。

### 8.5 卡片、列表与元信息

列表用来扫描同类对象；卡片用于确实独立的对象、图表或内容单元。不要因为一页有六段内容就默认做六张等高卡片。

元信息可以是无框的定义列表或分栏行。字段标签次级、值主要；不要把每个数值都放大成 KPI。整卡可点击时避免内部动作与卡片动作互相冲突；普通静态卡片不需要 hover 上浮。

### 8.6 折叠、提示和消息

简单展开可用原生 `details/summary`，保持状态图标与键盘操作。重要错误、执行条件和主结论不默认藏在折叠区。保真任务保留原默认开闭状态。

说明用中性块，警告用轻染背景和明确标题，不默认采用粗色边条。Toast 用于短暂操作反馈；需要用户处理的错误留在页面上。状态不要只在短暂消失的提示中出现。

### 8.7 菜单、弹窗与抽屉

默认优先就地编辑或展开；需要保护上下文、集中确认、选择复杂对象时使用弹窗。背景遮罩可用半透明炭黑，不默认加 blur。

弹窗应有标题、明确关闭机制、合理焦点管理；键盘不会落入遮罩后内容。菜单应位于正确的浮层层级，避免被表格滚动容器裁剪。工具库或原生 dialog/popover 能完成时，不另造脆弱的定位系统。

### 8.8 聊天、编辑器与文件区域

聊天使用清晰角色标识、合理阅读宽度和稳定的输入区。不同角色可用轻背景差异，不要求每条消息都做高饱和气泡。代码、引用、工具结果有各自语义和可折叠细节。流式输出避免自动滚动打断用户正在阅读的旧内容。

编辑器允许内容区域有更大可用空间；工具条保持小而稳定。上传区说明可接受内容和状态，错误显示在对应文件附近。设计不暗示不存在的上传、执行或连接能力。

## 9. 交互状态

不是每个组件都有全部状态；应覆盖其实际适用项。

| 状态 | 默认表达 | 常见错误 |
|---|---|---|
| Default | 明确功能与可点击性 | 一切像普通文字 |
| Hover | 小幅中性底色或边界变化 | 元素上浮、缩放、改变布局 |
| Focus | 2px 清晰 outline，适当外偏移 | 去掉 outline 或只靠 hover |
| Active | 更深底色、短暂按压反馈 | 位移过大导致目标移动 |
| Selected | 持续的底色／标记／字重差异 | 与 hover 无法区分 |
| Disabled | 减弱并正确禁止行为，必要时说明原因 | 仅降低透明度，仍然可点击 |
| Loading | 保持布局、解释等待范围 | 伪造进度、全页空白闪烁 |
| Error | 具体原因、定位、恢复动作 | 只用红边，无文字 |
| Empty | 说明为什么为空，提供合适下一步 | 为占位增加无关大插画 |
| Success | 简短确认，保留结果 | 为每次小操作播放庆祝动画 |

短操作可用局部 spinner；结构明确的内容加载可用静态或轻微骨架，不强制所有加载都闪烁。保留已有结果时，清楚标出正在刷新；错误时别把旧结果伪装成最新。

## 10. 表格、指标与专业文本

### 10.1 数据表

表头使用暖灰背景，行以轻分隔线或克制斑马纹组织；hover 仅帮助定位。排序列提供方向和语义；排序、筛选、选择不是仅供外观的假控件。

名称左对齐、数值右对齐、单位明确。使用 `font-variant-numeric: tabular-nums`；全表使用等宽字体应有具体需求。长名称可换行或截断并提供完整值；完整数据不因移动端被无提示删除。

宽表放在局部横向滚动区域，给滚动区域可访问名称并保证键盘可到达。必要时固定首列／表头，但检查层级和遮挡。不要靠整页横向滚动或把表格全部缩成 9px 解决问题。

### 10.2 指标

展示指标时同时说明名称、单位、范围／周期与状态。变化值是否有意义由业务决定，不能为了 dashboard 模板添加趋势箭头。缺失值、零和未计算是不同状态。

### 10.3 公式和代码

公式块用浅暖灰底和适当内边距，保留内容与可复制性。较长表达式局部滚动或依语法合理换行，不能插入改变含义的字符。代码高亮采用少量可辨颜色；默认不为了“技术感”使用巨大的深色终端面板。

## 11. 图表规范

### 11.1 视觉与数据分离

图表适配只修改呈现层：字体、背景、网格、线条颜色、hover label 和工具条。保真换肤必须保留序列身份、点值、日期、顺序、轴类型、范围策略、单位、图例、置信区间和计算方式。

降低采样、平滑、改轴起点、改变累计定义或默认隐藏曲线会影响解释，不属于纯配色适配。需优化性能时，单独说明方案与授权范围。

### 11.2 背景、网格和标签

图表底色与所在表面一致或透明；网格弱于数据线；零线在有意义时略清楚。轴标题、单位和刻度保证可读，工具条低调但可辨。不要把整个工具条容器设置为低透明度，导致图标和背景一起发灰。

折线宽度通常从 1.5–2px 起步，具体视密度而定；重要轨迹可更清楚。标记点、面积填充与每点标签只在帮助理解时添加。与数据相交的弱色细线要实际检查，不能仅凭色板觉得“温柔”。

### 11.3 系列调色板

推荐可读性较强的浅色主题起点：

| 序号 | 色值 | 角色 |
|---|---|---|
| 1 | `#a85940` | 陶土 |
| 2 | `#526f81` | 灰蓝 |
| 3 | `#806b35` | 深赭 |
| 4 | `#45413d` | 炭灰 |
| 5 | `#756c62` | 暖灰 |
| 6 | `#706078` | 灰紫 |

静态案例中使用过更浅的 `#ad654d / #78909e / #b39158 / #504c47 / #99918b / #665b70`。它体现审美方向，但浅色系列与背景的辨识度需逐图验证，不作为通用无障碍合格承诺。

类别名称或 ID → 固定颜色，不能按当前排序每次重新分配。连续量使用顺序色阶；正负偏离使用有明确中心的发散色阶；类别不用连续渐变。系列较多时考虑分面、小图、直接标注或用户选择，别无限增加相近棕色。

颜色之外使用虚实线、标记形状、直接标签或文字表格，特别是数条曲线重叠时。色盲条件下系列仍需可区分；低饱和并不自动意味着易区分。

### 11.4 交互和替代信息

hover 提供日期、系列、数值和单位；触控不能只依赖悬停。图例开关保持稳定状态，重绘不能无故重置用户选择。折叠区域展开后重新确认图表尺寸，避免绘制为零宽。提供可读摘要、数据表或下载作为适当补充，图像 alt 不足以承载复杂数据本身。

## 12. 响应式与内容韧性

断点由内容决定，约 640px / 960px / 1280px 可作为起点。先调整布局结构，再调整局部密度，不整体等比缩小。

- 侧栏在空间不足时收起或变抽屉，主体保持可用宽度。
- 双栏内容转单栏，保留逻辑阅读顺序。
- 工具栏允许换行，主要操作不被挤出视口。
- 长表格局部横向滚动，文本段落正常换行。
- 图表随容器重算尺寸，图例可换行，保留关键单位。
- 长链接、路径、文件名和无空格标识符有 overflow-wrap 或局部滚动策略。
- 字体放大、浏览器缩放、系统字体 fallback 和中文长文下重新观察布局。

不能用全局 `overflow-x: hidden` 掩盖未处理的溢出；这会把信息与焦点一起裁掉。

## 13. 可访问性与对比度

普通文字与背景至少 4.5:1，大字至少 3:1；这里的大字按标准定义约为 24 CSS px，或约 18.7 CSS px 的粗体。placeholder 同样需要可读。必要控件边界、图形和状态信息与相邻颜色通常需要 3:1，装饰性分隔线不等同于必要控件边界。细节和例外以 W3C 说明为准：[文字对比](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)、[非文字对比](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)。

WCAG 2.2 AA 的目标尺寸条款采用 24×24 CSS px 或符合其间距等例外；本规范对主要触控目标建议 44px，属于舒适度建议，不把它误写为 AA 的统一硬门槛。[目标尺寸说明](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)

必须检查真实前景／背景组合、透明度及覆盖状态，不能只检查 tokens 色板。可见焦点、正确标签、语义控件、逻辑焦点顺序、错误说明和键盘可达性与颜色同样重要。颜色值和截图通过不代表完整无障碍认证。

克制感与低对比不是同义词。必要时加深文字、控件边界和数据线；品牌色服从可读性。

## 14. 动效与反馈

常规状态转换默认 150–200ms，可按任务在 100–250ms 内调整。优先对颜色、边界和透明度指定具体 transition，避免 `transition: all`。用户触发的展开应自然、短促，不让用户等动画结束才能操作。

不采用页面逐段入场、卡片循环漂浮、弹跳按钮和持续光效。尊重 `prefers-reduced-motion`，关闭非必要动画和平滑滚动；业务上必需的进度变化仍以可理解方式呈现。

## 15. 主题、图像与文案

### 15.1 深色主题

只在产品需要时实施深色，不为了规范完整就要求每个项目同时实现。深色通过语义 token 替换：暖炭底、逐级略亮的表面、柔和亮字、更亮的陶土链接。不要自动反色、把浅色图表色板原样搬过去或让全部边框消失。

配套 tokens 包含深色起点，属于扩展建议；尚不能替代实际产品深色验证。表格 hover、表单错误、浮层、代码高亮和图表都需要检查。尊重用户明确主题选择，系统主题仅作为无选择时的可选默认。

### 15.2 图标与图像

图标使用同一家族、近似描边和尺寸，常用 16–20px；不混合 emoji、填充彩色图标和细线图标。图片只在帮助理解对象、内容或品牌表达时出现。无需为工具页专门生成背景图或抽象插画。

### 15.3 文案

新建界面用明确动作、具体对象与可恢复的错误说明。保留真实状态，不把“正在连接”“已完成”“智能分析”等词当装饰。换肤任务完全保留已有文案，文案问题可单独指出，不在样式修改中顺手改写。

## 16. 跨项目复用与实现边界

统一的是颜色角色、字体职责、控件语言、状态和层次方法；业务信息架构与功能因项目而异。React、Vue、服务端模板和纯静态 HTML 均可采用，不指定组件框架。

| 项目类型 | 保留的共同规则 | 可调整部分 |
|---|---|---|
| 数据工作台 | 纸面、统一控件、弱网格、语义色 | 更高密度、宽内容区、更多数据交互 |
| 知识库 | 暖色、阅读排版、清晰导航 | 更窄正文、更大段间距 |
| 项目管理 | 稳定状态、列表与编辑组件 | 看板、列表、详情等任务布局 |
| 设置中心 | 控件状态、表单与错误语言 | 字段分组、保存机制 |
| 聊天工具 | 字体、表面、输入与反馈 | 角色、消息结构、工具结果 |
| 品牌介绍 | 温和底色与编辑式标题 | 更大视觉尺度、经授权的图片与表达 |

建立项目自己的语义变量映射和少量共享 primitives；不要以设计规范为由重写技术栈。CSS 框架已有变量时映射进去；已有组件库时优先用 theme API。详细操作见 [工程适配](references/implementation.md)。

## 17. 保真换肤的交付标准

对原页面做样式预览时，“看起来更好”与“内容没有变化”是两个独立检查项。保存原始基线，在呈现层覆盖样式，图表配置使用副本。

核对原文、章节顺序、表格行列与值、公式、图表数据和路由语义；再检查控件、响应式与渲染。无需把项目特有的统计数量变成通用门槛。不能以 DOM 文本完全一致证明轴尺度、筛选结果或事件行为一致。

离线预览使用本地静态资源与快照。未实现的后端动作清楚显示为不可用或预览提示，避免点击后悄悄访问原服务。来源服务只用于经授权的一次性读取，不成为运行时依赖。

## 18. 常见偏离与修正

| 偏离 | 修正方向 |
|---|---|
| 默认绿色、每个成功态都变成大绿色卡片 | 中性为底，绿色只表达具体状态 |
| 只有暖白背景，其他仍是通用模板 | 统一字体职责、间距、控件和层次 |
| 整页平淡没有锚点 | 明确标题与主动作，提高必要文字对比 |
| 为避免 flat 添加玻璃和重阴影 | 用表面明度、线与间距建立分区 |
| 全部卡片相同尺寸、相同图标和副标题 | 按内容关系选列表、段落、图表或对象容器 |
| “高级感”变成 11px 浅灰全文 | 恢复正常正文大小、对比和阅读宽度 |
| 柔和曲线相互难辨 | 加深颜色、补线型／标签，保留系列身份 |
| 为了版面删列、改精度、缩短区间 | 回到原内容，使用滚动、换行和布局适配 |
| 每页各自重调颜色与圆角 | 共享变量与组件，只在真实例外处覆盖 |
| 把营销页大标题搬到管理台 | 按 Operate 模式缩小字阶与留白 |
| 只完成默认态 | 补齐实际涉及的焦点、错误、禁用等状态 |

## 19. 使用与维护

### 19.1 最小调用

已安装后：

> 使用 `$ochrelune-design` 为这个项目做温和编辑式设计。沿用现有框架，只调整视觉与组件一致性，保留文案、数据和功能。

未安装时：

> 读取 `ProphetLab/Design/ochrelune-design/SKILL.md` 并按其中规范完成当前任务。

若要新建界面，提供页面用途与必要功能即可，不需要重复输入全部色值。若要只换肤，明确“保留内容和行为”；若要信息架构重做，单独说明允许范围。

### 19.2 文件职责

- `SKILL.md`：代理入口、任务边界、读取路由和工作流程。
- `OchreluneDesign.md`：完整的跨项目设计规范，即本文。
- `assets/tokens.css`：可复用的颜色、字体、尺度和主题起点。
- `assets/primitives.css`：显式类名与作用域的基础组件示例。
- `references/implementation.md`：不同技术栈、保真和图表适配方法。
- `references/review.md`：完成前的适量检查和常见调用场景。
- `references/provenance.md`：出处、冲突裁剪、案例证据与限制。
- `agents/openai.yaml`：Codex 的显示名称与默认调用提示。

整个目录可迁移，无需依赖原研究快照或 FactorGTJA191。文档内的案例只用于说明；Skill 不自动安装、不发布网站、不连接外部服务。项目采用后，记录实际调整的字号、密度、品牌约束与状态例外即可，不要求另建复杂治理流程。
